# Primordis Agent Guide

This file defines the default operating rules for AI coding agents working in this
repository. It is the authoritative source for engineering standards and workflow.

## What Primordis is

Primordis is a GPU particle-life simulator being ported from a single Python file
(`Primordis.py`, built on pygame + moderngl + numpy) to **one Flutter app** that runs on
**Flutter Web (WASM)** and **native Flutter macOS**. All GPU compute lives *outside*
Flutter behind a single Dart `SimBackend` interface:

- **Web GPU** — browser WebGPU (WGSL) via `dart:js_interop` on an owned `<canvas>` (full 24k particles), falling back to a pure **Dart→WASM CPU** sim (~3–4k) where WebGPU is absent.
- **Native macOS** — the *same* WGSL kernel via **Dawn/wgpu-over-Metal through `dart:ffi`**, with a hand-written **Metal (MSL)** plugin as a fallback, plus a multi-core CPU isolate tier.

The UI, sliders, and sim parameters are **shared across all platforms**; only the compute
dispatch and the present/compositing path are platform-specific. See `docs/` for the PRD,
ADRs, and research summary.

## Read Order Before Coding

1. **The assigned task** in the `dgroup-standards` MCP server, scope `PRIMORDIS_WEB`.
   - `get_task_context(number)` when the number is known; otherwise `list_tasks(scope: "PRIMORDIS_WEB")` / `search_tasks` / `get_task`.
   - Do **not** treat `docs/tasks/` as authoritative — tasks 006+ have been migrated into the MCP server. Only the completed early tasks (001–004) remain as historical files.
2. **Flutter coding standards** — preferred via MCP: `get_coding_standards("flutter")`. This covers Riverpod, Freezed, Retrofit/Dio, GoRouter, `package:lint`, testing, accessibility, and versioning.
3. **Reusable org ADRs** — via MCP: `list_adrs` to enumerate, `get_adr(number)` to fetch (state management, routing, web rendering, URL strategy, etc.).
4. **Primordis-specific ADRs / PRD** — these remain file-based for now: `docs/adr/PRIMORDIS-ADR-0NN-*.md`, `docs/prd/PRIMORDIS-PRD-001-*.md`, `docs/research/`. Each task's "Related" section names the ones that apply.

## Repository Layout

- `lib/app/` — app shell, router (GoRouter), theme (Material 3).
- `lib/features/**` — feature-layer UI + providers (Riverpod). **No** `dart:js_interop` / `dart:ffi` here.
- `lib/shared/**` — shared constants/config (`PrimordisConfig`).
- `lib/sim/` — the simulation seam:
  - `lib/sim/sim_backend.dart` — the `SimBackend` interface (the only door to compute).
  - `lib/sim/kernel/primordis.wgsl` — the single shared WGSL compute kernel.
  - `lib/sim/backends/**` — per-platform backends (web WebGPU JS-interop, CPU fallbacks, macOS FFI/Metal). GPU/interop/FFI code is **quarantined here by design**.
- `test/**` — unit/widget tests mirroring `lib/`.
- `web/`, `macos/` — platform hosts. `Primordis.py` — the Python reference sim (parity source of truth).
- `docs/` — PRD, ADRs, research, and historical task files.

## Coding Standards

- **State management:** Hooks/Riverpod with annotation style and plain `Ref`. **No `setState`** for business state.
- **Models:** Freezed (immutable) + json_serializable where needed. Never hand-edit generated `*.g.dart` / `*.freezed.dart` — they are gitignored and regenerated by `build_runner`.
- **Navigation:** GoRouter (type-safe). **UI:** Material 3 + GoogleFonts.
- **Lint:** base is `package:lint` (`analysis_options.yaml`); CI enforces a **zero-warning** policy.
- **The sim seam:** UI reaches compute only through `SimBackend`. `dart:js_interop` (web WebGPU) and `dart:ffi` (macOS Dawn/Metal) live under `lib/sim/backends/**` and must never leak into `lib/features/**`.
- **Parity:** validation against `Primordis.py` is visual/statistical, never bit-exact (the original GPU binning is nondeterministic).
- **Accessibility:** this is a full-screen-motion app — honor `prefers-reduced-motion` / `MediaQuery.disableAnimations`; controls need `Semantics` and keyboard operability.

## Quality Gates

CI (`.github/workflows/ci.yml`, job `analyze-test`) runs on every PR and every push to `main`.
Reproduce it locally before pushing:

```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter analyze     # zero warnings
flutter test
```

When a change touches build/present paths, also smoke `flutter build web --wasm` and/or
`flutter build macos --debug` (full web-hosting and macOS packaging pipelines land in their
own tasks).

## Versioning

When Flutter/native code changes, bump `version:` in `pubspec.yaml` and keep the mirrored
`PrimordisConfig.version` constant in sync (semver).

## Branches, PRs, and Merging

- Ship work on a feature branch: `feat/task-<n>-<slug>`. Open the PR against `main` on `babernethy/primordis`.
- Keep harness `claude/*` worktree branches (under `.claude/worktrees/`) temporary and local; do not push them as feature branches.
- Every PR: request a Copilot review, address actionable comments, and wait for the `analyze-test` check to go green before merging.
- Update the MCP task (`Done` + `prLink`) when the PR opens.

## Conflict Resolution

Precedence order:
1. Direct user instruction.
2. Task-specific instructions in the assigned `PRIMORDIS_WEB` MCP task record.
3. Primordis ADRs (`docs/adr/`) and reusable org ADRs / Flutter standards (via MCP).
4. This guide.
