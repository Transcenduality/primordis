# Primordis parity harness

Validates each `SimBackend` (and the standalone WGSL kernel) against the original
`Primordis.py` reference — and against each other — on **visual/statistical**
criteria, **never bit-exact**. Owns PRIMORDIS-TASK-799; the substrate
PRIMORDIS-TASK-807 (Dawn/Tint vs browser/Naga atomics parity) builds on.

## Why parity is statistical, not bit-exact

The reference GPU binning is a single-buffered atomic scatter with a known
scatter race (`Primordis.py`), so **two runs of the reference itself diverge**
per-particle. Seeding also differs across implementations (NumPy PRNG vs
`dart:math` `Random`), so positional comparison is impossible. A *faithful* port
therefore means the simulation produces the **same kind of behaviour** —
clusters of the same character form, drift, and persist, with matching aggregate
statistics — not identical particle positions or pixels. This is the project-wide
"faithful = visually/statistically equivalent" contract (PRD non-goals,
PRIMORDIS-ADR-001, PRIMORDIS-ADR-006).

The one place a near-exact comparison is legitimate is **CPU-vs-CPU**: the CPU
tier's counting-sort binning is deterministic and bit-stable per seed+params, so
it reproduces its own fingerprint exactly. Never CPU-vs-GPU or GPU-vs-GPU.

## Known, documented divergence

The CPU tier does **not** port the `MAX_BIN_PARTICLES = 512` per-bin cap, so it
never drops over-cap particles from bin membership, whereas the GPU tiers and the
Python reference do. This is intentional (it makes the CPU tier *more* faithful,
never dropping particles). The metrics are all position-invariant aggregates that
tolerate this — none assume capped membership. Do not file "parity flaky" bugs
against inherent GPU nondeterminism or this cap divergence.

## Architecture (reusable library)

The diffing/statistics infrastructure is a **reusable pure-Dart library** under
`lib/sim/parity/` (UI-free, `dart:math` + `dart:typed_data` only), unit-tested
under `test/sim/parity/`, so PRIMORDIS-TASK-807 consumes it rather than
reinventing metrics:

| File | Role |
|------|------|
| `lib/sim/parity/parity_metrics.dart` | Primitives: `MetricGrid`, `binOccupancy` (the atomics-parity vector), `Moments`, minimum-image distance. |
| `lib/sim/parity/frame_metrics.dart` | `FrameMetrics.from` — the full position-invariant fingerprint of one frame (clusters, spacing, segregation, speed/KE, edge-density). |
| `lib/sim/parity/parity_bands.dart` | `Band` + `ParityBands.vsReference` (tight) / `.crossBackend` (loose) tolerance presets, each justified in comments. |
| `lib/sim/parity/parity_fingerprint.dart` | `ParityFingerprint` — a checkpoint time series; JSON (de)serialisation; `violationsAgainst`. |
| `lib/sim/parity/parity_runner.dart` | `ParityBackend` interface (the pluggability seam) + `runParity`. |
| `lib/sim/parity/cpu_parity_backend.dart` | The deterministic CPU tier adapter (the primary anchor). |
| `lib/sim/parity/raw_snapshot.dart` | Ingests raw SoA snapshots from out-of-process backends (WGSL kernel, later Dawn) and reduces them with the *same* Dart metrics. |

Adding a backend to the suite requires only implementing `ParityBackend` (or
exporting raw snapshots) — **no new metric or band code**.

## Statistical metrics (all position-invariant)

- **Cluster count** — connected components of dense grid bins (8-neighbour
  toroidal), on the sim's own 11×7 / `MAX_RADIUS=96` grid.
- **Occupancy moments** — per-bin count distribution; variance signals
  clustering. `binOccupancy` is the reusable atomics-parity vector.
- **Nearest-neighbour spacing** (minimum-image) — repulsion/attraction balance.
- **Per-type segregation index** — do the asymmetric matrices separate types.
- **Speed & kinetic-energy** — the Drift/friction proxy (higher Drift ⇒ faster
  decay; asserted as a behavioural response, not just a value).
- **Population conservation** — exact; the toroidal wrap must lose no particle.
- **Edge-density excess** — toroidal correctness: no artificial seam pile-up
  (area-normalised, because the world is not an integer number of bins wide).

## Running the harness

The Dart parity suite runs in the standard CI `analyze-test` job (pure Dart, no
GPU):

```sh
flutter test test/parity test/sim/parity
```

## Regenerating the committed fixtures

Fixtures live in `test/parity/fixtures/`. See that directory's README for what
each file is.

### 1. Shared seed (byte-identical initial condition)

Every backend must start from the same concrete initial arrays (the two PRNGs
can't reproduce each other):

```sh
dart run tool/parity/export_seed.dart --seed 42 --particles 3000 --types 32 \
  > test/sim/kernel/harness/seed.json
```

### 2. CPU reference fingerprint (committed, CI-checked)

The deterministic CPU tier is the primary anchor. Its fingerprints
(`cpu_reference_default.json`, `cpu_reference_highdrift.json`) are regenerated by
temporarily printing `runParity(...).toPrettyJson()` for
`ParityHarnessConfig.defaults()` / `.highDrift()` (see the generator note in the
fixtures README). Because the CPU tier is bit-stable, this needs no GPU.

### 3. WGSL kernel fingerprint (optional, needs a WebGPU host)

```sh
cd test/sim/kernel/harness
node export_fingerprint.mjs      # -> ../../../parity/fixtures/wgsl_kernel_snapshots.json
```

Requires the prebuilt Dawn (`@kmamal/gpu`). Absent this fixture the WGSL parity
test **skips** (CI stays green without a GPU); present, it asserts the kernel is
within the cross-backend band.

### 4. Python reference fingerprint (optional, needs OpenGL 4.3)

```sh
pip install numpy moderngl
python3 tool/parity/capture_reference.py \
  --seed test/sim/kernel/harness/seed.json \
  --out test/parity/fixtures/py_reference_snapshots.json \
  --attraction 32 --repulsion 32 --friction 0.25 \
  --steps 240 --checkpoints early=0,mid=60,steady=239
```

Runs the reference's *exact* compute shaders headlessly. Commit the output to
lock the reference baseline; the Dart side ingests it via `raw_snapshot.dart`
and compares under the cross-backend band.

All scenario constants (seed, counts, sliders, steps, checkpoints) **must** match
`ParityHarnessConfig.defaults()` in
`test/parity/parity_harness_support.dart` — that Dart config is the single source
of truth for the scenario.
